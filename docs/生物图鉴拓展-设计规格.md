# 生物图鉴拓展（tl_creature_bestiary）设计规格

日期：2026-09-04  
目标版本：Minecraft 1.20.1 / Forge 47.4.10  
基础依赖：tl_domesticate_more_creatures（TDMC）  
新模组：生物图鉴拓展  
Mod ID：`tl_creature_bestiary`  
包名：`com.szypxj.tlcreaturebestiary`  
初始版本：`1.0.0`

## 1. 目标与范围

本项目新增一个独立 TDMC 附属模组“生物图鉴拓展”，核心闭环为：

1. 玩家真正使用望远镜持续扫描一个生物约 1 秒。
2. 服务端验证扫描目标、距离、视线和望远镜使用状态。
3. 首次扫描成功后，将对应 `EntityType` 永久录入该玩家在当前世界的图鉴。
4. 望远镜标题显示 1～9 星危险程度，并始终绘制 9 个星位。
5. 图鉴页面显示已解锁物种的基础三维能力、危险星级、是否可驯服、驯服食物。
6. 未扫描物种保留未知占位，不泄露名称、星级和驯服信息。

第一版不实现掉落物、群系、击杀统计、生态关系、弱点抗性、故事文本、图鉴奖励、Boss 专属页面等扩展功能。

## 2. 工程边界

### 2.1 TDMC

TDMC 只增加必要的公共扩展 API 和 UI 扩展点，不内置图鉴业务逻辑。

TDMC 负责：

- 提供“TDMC 第一次接管前”的基础属性快照能力。
- 提供生物基础资料查询 API。
- 提供驯服规则和显示食物的稳定查询 API。
- 提供望远镜标题额外组件扩展点。
- 提供经服务器验证的望远镜扫描事件扩展点。
- 将已有 `PanelActionRegistry` 真正接入属性面板 GUI。

### 2.2 tl_creature_bestiary

附属模组负责：

- 危险星级算法和星级渲染组件。
- 玩家图鉴解锁数据。
- 扫描进度与首次录入逻辑。
- 图鉴页面、搜索和详情展示。
- 调用 TDMC API 获取基础能力与驯服资料。
- 自己的网络频道与同步包。

附属不通过 Mixin 直接修改 TDMC 望远镜或属性面板。

## 3. 收录范围与条目标识

图鉴收录所有非玩家 `LivingEntity`：

- 原版生物。
- 其他模组生物。
- Boss。
- 被 TDMC 过滤器排除、不受 TDMC 等级系统影响的生物。

玩家不进入图鉴。

每个条目使用 `EntityType` 注册 ID 唯一标识，例如：

- `minecraft:zombie`
- `minecraft:polar_bear`
- `examplemod:boss_entity`

同一个 `EntityType` 的幼年、成年、不同外观、不同 NBT、不同 TDMC 等级、精英状态均属于同一图鉴条目。

## 4. “基础属性”的最终定义

### 4.1 基础血量

本项目所说的“基础血量”定义为：

> 某个 `LivingEntity` 在 TDMC 第一次初始化该实体之前，`MAX_HEALTH` 的 `AttributeInstance.getBaseValue()`。

因此：

- 原版默认基础值算基础血量。
- 其他模组如果在 TDMC 初始化之前通过 `setBaseValue()` 或等价方式修改 `MAX_HEALTH` 基础值，该修改计入基础血量。
- TDMC 自己的等级、属性点、天赋、驯养、精英、印记等后续加成不计入基础血量。
- 装备、药水和临时 Buff 不计入基础血量。
- 其他模组如果只通过 `AttributeModifier` 叠加最大生命，而没有改变 `baseValue`，该 Modifier 不计入“基础血量”。

### 4.2 捕获时机

TDMC 新增内部基础属性快照组件，并在 `LevelService.initializeIfNeeded(LivingEntity)` 的最前部、任何 `ProgressData` 创建和 `AttributeService.applyAll()` 之前调用。

捕获顺序：

1. 实体已由 Minecraft 和其他模组创建。
2. 读取当前 `MAX_HEALTH / ATTACK_DAMAGE / MOVEMENT_SPEED` 的 `baseValue`。
3. 将快照绑定到实体持久数据。
4. TDMC 再执行等级、属性点和其他自身加成。

若实体已经存在 TDMC 基础快照，则不得覆盖，以免后续重新应用属性时把 TDMC 结果误记为基础值。

若某个属性不存在，则对应基础值为 0；若 `MAX_HEALTH` 不存在或小于等于 0，该实体不参与危险等级计算，但仍可作为图鉴未知条目处理。

### 4.3 旧存档兼容

对于升级前已经被 TDMC 初始化、但没有基础快照的旧实体：

- TDMC 先移除自己可识别的受管 Modifier。
- 读取剩余的属性 `baseValue` 作为迁移基础值。
- 恢复/重新应用 TDMC 受管 Modifier。
- 迁移后写入基础快照，后续不再重复推导。

如果无法可靠推导，则回退到 `DefaultAttributes` 的基础值，并记录一次警告；不得将当前 TDMC 加成后的最大生命直接当成基础血量。

## 5. 危险程度算法

危险程度范围固定为 1～9 星。

对于基础血量 `H`：

```text
star = floor(sqrt(H / 100))
star = clamp(star, 1, 9)
```

等价阈值：

| 星级 | 最低基础血量 |
|---|---:|
| 1★ | 0（不足 1 星强制按 1 星） |
| 2★ | 400 |
| 3★ | 900 |
| 4★ | 1600 |
| 5★ | 2500 |
| 6★ | 3600 |
| 7★ | 4900 |
| 8★ | 6400 |
| 9★ | 8100 |

大于等于 8100 仍封顶 9 星。

危险等级只使用基础血量，不使用当前血量，也不使用 TDMC 加成后的最大血量。

## 6. 九星显示组件

所有危险等级 UI 始终绘制 9 个固定星位：

- 已达到的星：亮起。
- 未达到的星：暗色。
- 例如 3 星就是 3 颗亮星 + 6 颗暗星。

望远镜和图鉴详情页必须复用同一个星级渲染组件，保证尺寸、间距和颜色一致。

颜色通过渲染色值控制，不在 Java 可见文本中硬编码 `§` 颜色码。

## 7. 望远镜扩展

### 7.1 标题星级

TDMC 望远镜现有标题右侧增加一个可扩展区域。

图鉴附属注册后，标题表现为：

```text
生物名称  [九星危险度]  Lv.X
```

具体排版保持“星级在生物名字右边”的要求；TDMC 等级文本继续保留在后方。

对于不受 TDMC 等级系统影响的 `LivingEntity`：

- 仍允许望远镜识别其名称和危险星级。
- 不强制显示 TDMC 等级、天赋、眩晕等无效栏目。

### 7.2 扫描条件

完成扫描必须同时满足：

- 玩家正在 `isUsingItem()`。
- 当前使用物品为原版望远镜 `Items.SPYGLASS`。
- 准星持续指向同一个 `LivingEntity` 实体实例。
- 持续时间约 20 Tick（1 秒）。
- 目标在 TDMC 配置允许的望远镜检查距离内。
- 玩家对目标有直接视线。

仅手持望远镜、不处于使用状态时，不累积扫描进度。

目标实体 ID 变化、视线中断、距离超限、停止使用望远镜时，扫描进度立即归零。

### 7.3 服务端权威

客户端仅发送当前候选目标，不得直接声明“扫描完成”。

服务端负责：

- 验证玩家正在使用望远镜。
- 获取目标实体。
- 验证目标是非玩家 `LivingEntity`。
- 验证距离。
- 验证视线。
- 维护连续 Tick 计数。
- 达到 20 Tick 后触发公共扫描完成事件。

附属监听该事件并执行图鉴录入。

## 8. 玩家图鉴存档

每个玩家独立保存一个已解锁 `EntityType` ID 集合。

示例：

```text
minecraft:zombie
minecraft:polar_bear
examplemod:boss_entity
```

数据特性：

- 死亡保留。
- 退出重进保留。
- 换维度保留。
- 同一个世界中长期保存。
- 新世界重新收集。
- 不跨世界共享。

存档只记录“是否发现”，不固化：

- 危险星级。
- 基础三维图数值。
- 驯服规则。
- 驯服食物。

这些资料每次根据当前 TDMC / 模组配置动态读取，因此更新配置后不要求玩家重新扫描。

## 9. 图鉴页面

### 9.1 入口

TDMC 属性面板通过 `PanelActionRegistry` 动态生成附属按钮。

图鉴附属注册：

```text
生物图鉴
```

点击后进入图鉴页面。

图鉴页面的“返回”返回进入前的 TDMC 页面，不直接关闭 GUI。

第一版不额外占用快捷键。

### 9.2 风格

继承 TDMC UI 视觉规范：

- 深蓝主题。
- 约 75% 透明度。
- 背景模糊/压暗。
- 淡蓝悬停。
- 字体阴影。
- 按钮对齐。
- “返回”而不是“关闭”。

### 9.3 左侧列表

左侧包含：

- 搜索框。
- 图鉴条目列表。
- 解锁数量 / 总数量进度。

已解锁显示真实名称和图标/模型占位信息。

未解锁统一显示 `????`，不显示真实名称、星级、驯服状态。

搜索仅针对已解锁条目匹配：

- 本地化名称。
- 英文/当前语言显示名。
- 注册 ID。

未解锁条目不通过搜索泄露身份。

### 9.4 详情区

选择已解锁物种后显示：

- 生物名称。
- 9 星危险程度。
- 三维能力图。
- 是否可驯服。
- 驯服食物及数量。

未选择或未解锁条目不显示真实资料。

## 10. 图鉴基础三维图

图鉴三维图复用 TDMC 的 `SpyglassRadarMath` 百分位算法和相同视觉样式，但输入使用基础快照而不是当前实体最终属性。

三轴：

- 力量：基础 `ATTACK_DAMAGE baseValue`。
- 生命：基础 `MAX_HEALTH baseValue`。
- 速度：基础 `MOVEMENT_SPEED baseValue`。

望远镜现有三维图继续表示眼前个体的实际能力；图鉴表示物种基础能力，两者职责分离。

### 10.1 物种基础资料来源

优先级：

1. 当前世界中该 `EntityType` 已捕获的 TDMC 前基础快照。
2. 若尚未有实例快照，则回退到 `DefaultAttributes`。

运行时按 `EntityType` 缓存基础资料，并在资源/配置重新加载或服务器重新启动后重建，不写死进玩家图鉴存档。

## 11. 驯服资料

图鉴不维护独立驯服配置。

TDMC 增加稳定公共查询 API，提供：

- 当前 `EntityType` 是否存在有效驯服规则。
- 驯服方式。
- 所需玩家等级（API 保留，第一版详情页可不显示）。
- 可显示的原生食物。
- 额外驯服食物。
- 每种食物数量。

若无有效规则：

```text
可驯服：否
```

若存在有效规则：

```text
可驯服：是
驯服食物：...
```

当 `taming_rules.toml` 更新后，图鉴下次读取自动显示最新结果。

## 12. TDMC 公共 API 设计

### 12.1 CreatureInfoApi

职责：提供稳定、只读的生物基础资料查询。

建议接口能力：

```text
getEntityId(EntityType<?>)
getBaseStats(LivingEntity)
getBaseStats(EntityType<?>)
getTamingInfo(EntityType<?>)
isTdmcAffected(EntityType<?>)
```

`BaseStats` 至少包含：

```text
maxHealth
attackDamage
movementSpeed
source
```

其中 `source` 用于标记实例快照或 `DefaultAttributes` 回退来源。

### 12.2 SpyglassInspectionApi

职责：为附属提供望远镜扩展点，而不是暴露整个内部网络包。

能力：

- 注册标题附加渲染器。
- 注册服务器扫描完成监听器。
- 查询当前被验证的望远镜目标。

扫描完成事件至少提供：

```text
ServerPlayer player
LivingEntity target
ResourceLocation entityTypeId
```

### 12.3 PanelActionRegistry 接通

TDMC `AttributePanelScreen.init()` 读取 `PanelActionRegistry.actions()`，按照现有深蓝按钮样式生成按钮。

要求：

- 排序稳定。
- 不与 TDMC 内置按钮重叠。
- 屏幕缩放后重新布局。
- 重复 ID 注册继续报错，避免附属冲突被静默覆盖。

## 13. 附属模组网络设计

`tl_creature_bestiary` 使用独立 SimpleChannel，不修改 TDMC 固定协议版本。

第一版最少需要：

### S2CBestiaryFullSync

登录/重生/需要重同步时发送：

- 已解锁 `EntityType` ID 集合。

### S2CBestiaryUnlock

首次扫描成功时增量发送：

- 新解锁的一个 `EntityType` ID。

基础星级、基础三维图和驯服资料不每 Tick 网络同步。

能在客户端安全从注册表和 TDMC API 得到的数据优先本地读取；服务器权威数据只同步解锁状态。

## 14. 首次录入反馈

扫描首次成功后：

- 屏幕显示简短提示“已录入：<生物名>”。
- 播放轻量原版提示音。
- 不写入聊天栏。
- 已解锁物种再次扫描不重复提示。

所有玩家可见文本必须使用 I18N。

## 15. 性能约束

明确禁止：

- 每 Tick 遍历世界全部实体。
- 每 Tick 遍历全部 `EntityType` 创建实体实例。
- 每 Tick 发送整本图鉴。
- 每 Tick 解析 `taming_rules.toml`。
- 渲染循环中发送网络包。

允许：

- 只跟踪正在使用望远镜玩家的单个准星目标。
- `EntityType` 级基础资料缓存。
- 图鉴打开时构建一次当前列表。
- 驯服规则由 TDMC 已有缓存/管理器提供。

## 16. 异常与兼容策略

- 实体类型已从模组包中删除：玩家存档中的旧 ID 保留但客户端忽略，不崩溃。
- `EntityType` 无默认属性：仍可作为未知/已发现条目，但三维图缺失轴显示 0。
- 无 `ATTACK_DAMAGE`：力量为 0。
- 无 `MOVEMENT_SPEED`：速度为 0。
- 无有效 `MAX_HEALTH`：危险度最低按 1 星显示，同时记录数据来源异常而不崩溃。
- TDMC 驯服规则热重载/重新载入后，图鉴使用最新规则。
- 被 TDMC 排除的 LivingEntity 仍可扫描和解锁，只是 TDMC 特有等级资料不显示。

## 17. 测试与验收

### TDMC API 回归

- 未安装图鉴附属时，TDMC 行为与现状一致。
- 原有属性面板、宠物面板、望远镜、骑乘、天赋、背包不回归。
- `PanelActionRegistry` 无注册项时不产生空白按钮。
- 基础快照在 TDMC 第一次加成前写入，后续 `applyAll()` 不覆盖。

### 基础血量兼容

构造测试：

1. 原版牛基础 10：危险度 1 星。
2. 外部模组在 TDMC 前执行 `MAX_HEALTH.setBaseValue(500)`：危险度 2 星。
3. TDMC 再把最终最大生命提高到 900：危险度仍为 2 星。
4. 外部模组只添加生命 AttributeModifier 而不改变 baseValue：危险度仍按 baseValue。
5. 旧存档无快照实体：迁移后不能把 TDMC 最终生命误当基础血量。

### 星级边界

验证：

- 99 → 1 星。
- 100 → 1 星。
- 399 → 1 星。
- 400 → 2 星。
- 899 → 2 星。
- 900 → 3 星。
- 8099 → 8 星。
- 8100 → 9 星。
- 20000 → 9 星。

### 扫描

- 手持但不使用望远镜：不扫描。
- 持续对准同一实例 20 Tick：解锁。
- 19 Tick 移开：归零。
- 同物种换另一实体：重新计时。
- 隔墙：不扫描。
- 超距离：不扫描。
- 玩家目标：不扫描。
- 被 TDMC 排除的模组生物：仍可扫描。

### 图鉴

- 每玩家解锁独立。
- 死亡/换维度/退出重进保留。
- 新世界不共享。
- 未解锁不泄露名称和星级。
- 修改 `taming_rules.toml` 后无需重新扫描即可更新驯服资料。
- 搜索仅匹配已解锁条目。

## 19. 已确认决策摘要

- 新附属独立成模组，不把图鉴业务塞进 TDMC。
- 图鉴覆盖所有非玩家 LivingEntity。
- 物种按 EntityType 注册 ID 唯一标识。
- 危险度为固定 1～9 星，阈值为 `100 × 星级²`，9 星封顶。
- 望远镜和图鉴永远显示 9 个星位，达到的亮起，其余变暗。
- 扫描必须真正使用望远镜并持续对准同一实例约 1 秒。
- 解锁数据按玩家、按世界保存。
- 未解锁条目不泄露真实资料。
- 图鉴三维图显示基础能力，望远镜显示当前个体能力。
- 驯服资料动态读取 TDMC 当前规则。
- 图鉴入口通过 TDMC 公共面板动作 API 注入。
- 其他模组在 TDMC 第一次初始化前对属性 `baseValue` 的修改计入基础属性。
- TDMC 自己的所有后续加成不计入危险度和图鉴基础三维图。
